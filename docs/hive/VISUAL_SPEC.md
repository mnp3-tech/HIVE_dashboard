# HIVE dashboard - visual specification (measured)

**Status:** measurement + plan. GAP-5 stays OPEN. Nothing in this document is data for the dashboard: the target image is visual direction only, and every number, name, provider mapping and status in it (72 %, 1.31 TB, "Online", "ACTIVE", Admin, ...) is illustrative and is never reproduced as a value.

Generated by `tools/make_visual_spec.py` from `docs/hive/measurements/target.json` (tools/measure_target.py) and `ours-before-*.json` (tools/measure_ours.mjs, baseline commit f37affd). Target tolerance about +-2 px at 1671x941. Side-by-side and overlay images: `docs/hive/screenshots/compare-after-*.png` (previous phase), `overlay-before-*.png` (target outlines drawn over the current UI).

## 1. Architecture: local-first hybrid 2.5D
```
layer 0  WALLPAPER   one local raster (nebula + stars + circuit traces ONLY), CSS background, cover-fit        [decorative, static]
layer 1  CORE ART    local canvas (vortex/accretion, pre-rendered once) + local SVG (rings, ring nodes,           [decorative + state tint]
                     connector curves, agent icons, planet); parallax = at most a tiny CSS transform
layer 2  STAGE       a 16:9 reference stage (1671x941 units) scaled by k = min(vw/1671, vh/941); DOM panels are   [truth]
                     absolutely positioned on it from the planned rectangles in section 3.1
layer 3  LIVE DOM    every label, number, status, row, button, approval and chip is HTML/SVG-text in the DOM,     [truth]
                     driven by hive-core.js / hive-ops.js; nothing live is ever drawn into a raster
```
Rules: no Unity, no remote Spline embed, no CDN/runtime fetch; all assets are files in this repository and are served by the local server; no text, telemetry, numbers, provider states or approvals in any raster; reduced motion disables every animation; UNKNOWN/UNVERIFIED states keep their dim, desaturated look (the wallpaper never changes with state); `hive-core.js` remains the source of truth for CORE state, movement and transport.

### 1.1 Stage scaling and viewports that are not 16:9
k = min(vw/1671, vh/941). The stage is centred; the wallpaper fills the whole viewport (cover). At 1280x720, 1920x1080 and 2560x1440 k = 0.766, 1.149, 1.532. A wider or taller window letterboxes the stage over the wallpaper (no distortion, no extra panels). Absolute minimums stay in force: gutters >= 10 px, body text >= 10 px, so `max(10px, calc(var(--k) * N))` is used where the scaled value would drop below them.

### 2.3 Observations that contradict the current implementation
- **Rails are not full height.** Target left rail ends at y = 790 (84.0 % of H) and the right rail at y = 611 (64.9 %); the composer ends at 880 (93.5 %). The implementation anchors both rails to the composer line (last phase). That choice was wrong for parity.
- **Rails are unequal.** Left rail width 259 px (15.5 % W), right rail 332 px (19.9 % W). The implementation uses two equal rails of 17 % W.
- **The card row spans the centre only** (x 330..1276), not the full width between the rails, and the five cards have different widths (231, 167, 191, 191, 109 px).
- **The CORE is not horizontally centred in the target:** ring centre x = 814.9 (48.77 % W; centred would be 50 %), i.e. 20.6 px left of centre. The project spec requires the CORE centred; see 3.1 for the transform that satisfies both.

## 8. Wallpaper specification (PLAN: not built yet)
- Planned: one local file generated by a committed, deterministic script (`tools/make_wallpaper.py`, seeded; Pillow + numpy, dev-time only). The generated JPEG is committed under `assets/` and served locally.
- Content: nebula clouds, star field (several depths), faint circuit traces, subtle dark vignette. **Nothing else.** No text, no digits, no gauges, no rings, no panels, no icons, no provider logos, no UI chrome, no state colours that could be misread as a status.
- Size/format: 2560x1440 (16:9), JPEG q~85, target <= 600 KB; CSS `background: url(...) center/cover`, `background-color` fallback so the shell is usable if the file is missing.
- The wallpaper is static: it never changes with CORE state or data.
- Automated checks planned: file exists, 16:9, byte budget, generator source contains no text-drawing calls, no external URL in html/css/js, zero off-origin requests at runtime, wallpaper hash recorded.

## 9. CORE renderer specification and Rive evaluation (PLAN: not built yet; the Rive decision is made now)
CORE art = a pre-rendered local canvas (accretion disk with additive-blend streaks, glow, lens ring) rotated only by CSS in IDLE/WORKING, plus local SVG for rings, ring nodes, connectors, agent icons and the planet. State tint continues to come from `hive-core.js` (`deriveCoreState` -> `visualClass`) through CSS classes/filters; the renderer is a pure view: `apply({state, tone, motion, reduced})`, no logic of its own.

**Rive: evaluated, not adopted now.** Reasons: (1) it needs a `.riv` file authored in the Rive editor, which is not available here, and a runtime (JS + WASM) that is a large new dependency against the project's "no large dependencies / no WebGL" rule; (2) a canvas/SVG renderer has not yet been tried at the fidelity bar below; (3) any Rive runtime would have to be vendored into the repo (no CDN). **Adoption criteria** (all must hold): after a canvas/SVG attempt the owner still rates the CORE as the main visual gap; a `.riv` authored with state inputs matching the 8 CORE states exists; runtime and asset are vendored locally with licences recorded; state/movement/transport remain in `hive-core.js`; reduced motion pauses the artboard; a canvas fallback remains for UNKNOWN/offline load failure.

## 10. Differences, ranked by visual weight (what the next phase changes)
1. Layout: absolute normalised stage instead of a full-height 3-column grid (rails shorter, unequal widths, centre-only card row) - sections 2.3/3.
2. Type scale: panel titles at 0.81 % of H versus 1.28 % in the target; node names/labels similar gap - section 6.
3. CORE: ring 22.5 % vs 25.2 % of H, nodes and planet ~1.2-1.7x too small, agents on one circle instead of the measured angles/radii - section 5.
4. Background and vortex fidelity: procedural SVG strokes vs a rendered wallpaper and a layered canvas vortex - sections 8/9.
5. List/row density and icons inside the panels (pitches in section 6) - the target's density comes from illustrative content that must not be invented; only the geometry/typography is adopted.
6. Deliberately kept differences (truthfulness): UNKNOWN/gray states, no ACTIVE/Online, no Admin/bell/settings, no Logs label, no provider mapping, disabled Layout controls, English labels.

## 11. Verification plan
Overlay and side-by-side screenshots at 1280x720, 1920x1080, 2560x1440 (fixture and live-adapter); `tools/measure_ours.mjs <label>` re-measures and this document is regenerated; panel deltas must be <= 1.5 percentage points of W/H except where section 10 lists a deliberate deviation; existing E2E suites (shell, core, chat, system, visual) must keep passing; new checks for wallpaper (no text, local-only, byte budget), stage scaling (k, minimum gutter and text floors), CORE centring (+-2 px), reduced motion. GAP-5 closes only on the owner's explicit acceptance of the side-by-side review.
